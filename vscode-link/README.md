# Agent Usage Link

Bundled VS Code UI extension for the personal Agent Usage app. The desktop app installs its local VSIX through Code's CLI on the first terminal-linked click, and only when Code does not already list this version. No Marketplace publication or dependency download is required.

The `/open` URI accepts validated Claude/Codex session identity, process ancestor ids and a workspace path. In the focused matching workspace it shows an existing terminal with a matching process id. It never sends terminal text or creates a terminal. Missing terminals fall back to a fixed provider conversation URI. For 15 seconds after the helper wakes (a link that launched VS Code, or the first link in a new window) it waits for restored terminals before falling back. Remote workspace shell ids must match the collector; a Windows WSL wrapper pid may not match.

Package: `python3 scripts/package-vscode-link.py`. Tests: `node --test tests/test-session-open.cjs`. Windows focus/installation require a device check.

Version 0.2.0 adds `/resume` for saved Claude, Codex and Antigravity CLI sessions. The desktop resolves an account/session ID against collector history before constructing a validated URI containing the remote authority, workspace, account home and optional live process IDs. The helper focuses a matching existing terminal on that host. Otherwise it opens the SSH/WSL workspace in a new window, persisting the validated request locally for that window to consume after startup. Requests expire after five minutes and are not synchronized. The helper starts a login Bash terminal with the fixed resume command and shell-quoted account home; it sends no prompt and does not change CLI permission settings. Untrusted workspaces cannot launch a resume terminal. Tests: `tests/test-session-history.cjs` and `tests/browser/notch-history.cjs`.

Version 0.2.1 packs both `/open` and `/resume` targets into URL-safe base64 JSON. This survives VS Code decoding its query before the handler sees it, and avoids the router's reserved `session` parameter. On a helper upgrade, the desktop asks Code for one fresh window so an old running extension cannot silently drop the first history link. History links also include a random one-use loopback receipt endpoint; the UI helper reports received, opened or error, allowing the app to distinguish starting Code from opening a terminal. The endpoint is local-only, requires the nonce and rejects browser-origin requests. Connection/trust failures and acknowledgement timeouts are shown in the history dropdown.

Version 0.2.2 keeps history sessions in the active Code window. The session can be outside the open editor folder when the remote authority matches. Otherwise the Windows UI helper creates a terminal with a local `file:` working-directory URI, selecting Code's local terminal backend even in an SSH window. It launches fixed `ssh.exe -t <target>` or `wsl.exe --distribution <distro>` arguments, preserves the saved remote working directory and account, and runs the shell-quoted resume command. The current workspace is not reopened or replaced. Repeated clicks focus the created tab; exited tabs are recreated. Other platforms retain the remote-folder fallback. Trust checks still block new resume terminals in untrusted workspaces.

The desktop prepares this helper at startup and uses normal active-window URI routing, with `--reuse-window` and without `_blank`. Reload an already-open Code window once after an app update so its running extension host loads the new helper. Tests cover aliases and workspaces, connector quoting through both remote shell parses, WSL arguments, trust, startup preparation and loopback receipts.

Version 0.2.3 names newly resumed terminal tabs with Codex, Claude or AGY and the saved session title. Missing titles fall back to the workspace name, then the short session ID. Labels strip control and directional formatting characters, collapse whitespace and stop at 80 characters; this metadata never enters a shell argument. Already-open terminals keep their existing names.


Version 0.2.4 preserves Claude's default configuration: on the remote host, a home matching `$HOME/.claude` runs with `CLAUDE_CONFIG_DIR` unset, keeping the global onboarding file at `~/.claude.json`. Custom homes still set that variable. Codex continues using the selected account's `CODEX_HOME`. Created terminals include a provider/remote/home/session identity in `creationOptions.env`, allowing restored tabs to be recognized after extension reload without sending terminal text or relying on display names. Existing manual terminals still require a matching remote process ID. The desktop refreshes collector metadata and retains saved terminal ancestry rather than replacing it with an empty alert-feed entry.

Version 0.2.5 resolves different SSH aliases with the local OpenSSH client's `-G` configuration output, without connecting. Matching requires the same effective hostname, username, port and proxy route. Thus `fab@homelab` can focus a terminal in `SSH: homelab` when both describe the same connection; different users or hosts cannot match by a coincidental process ID. Equivalent connections use the window's existing remote authority for new terminals. Fresh process ancestry takes precedence over scoped helper tabs, and exited terminals are excluded. A freshly confirmed live session with no matching or scoped terminal reports an error instead of starting a duplicate. Closed sessions retain normal resume behavior. Configuration failures do not imply a match. Reload an already-open VS Code window once after installation to load this helper.
